# 개인 프레임워크 설계

## 핵심 철학

> **프로젝트를 할수록 프레임워크가 성장하고, 다음 프로젝트가 더 빨라지는 복리 효과**

```
프로젝트 1: 인증 모듈 처음 개발 (16시간)
프로젝트 2: 인증 모듈 재사용 + 결제 모듈 처음 개발
프로젝트 3: 인증+결제 재사용 + 채팅 모듈 처음 개발
...
프로젝트 10: 대부분의 기능이 모듈로 존재 → 커스터마이징만 (전체 50~70% 시간 절약)
```

## 모듈 분류 체계

### 1차 분류: 카테고리

명세서 템플릿의 `feature.category`와 1:1 매핑

| 카테고리 | 설명 | 예시 모듈 |
|---------|------|----------|
| `auth` | 인증/인가 | `auth_social`, `auth_jwt`, `auth_rbac` |
| `payment` | 결제/정산 | `payment_toss`, `payment_stripe`, `payment_escrow` |
| `chat` | 메시징 | `chat_websocket`, `chat_rooms` |
| `search` | 검색/필터 | `search_fulltext`, `search_filter` |
| `notification` | 알림 | `noti_push`, `noti_email`, `noti_sms` |
| `file` | 파일 관리 | `file_upload_s3`, `file_image_resize` |
| `admin` | 관리자 | `admin_dashboard`, `admin_user_mgmt` |
| `analytics` | 분석 | `analytics_basic`, `analytics_event` |
| `social` | 소셜 | `social_follow`, `social_like`, `social_share` |
| `location` | 위치 기반 | `location_map`, `location_nearby` |
| `content` | 콘텐츠 | `content_crud`, `content_editor`, `content_tag` |
| `moderation` | 신고/관리 | `mod_report`, `mod_block`, `mod_autofilter` |
| `infra` | 인프라/공통 | `infra_logging`, `infra_error_handler`, `infra_rate_limit` |

### 2차 분류: 기술 스택

각 모듈은 사용 기술에 따라 세분화

```
auth_social/
├── auth_social_python/     # FastAPI + Python 구현
└── auth_social_nextjs/     # Next.js Auth 구현

payment_toss/
├── payment_toss_python/    # FastAPI + 토스페이먼츠
└── payment_toss_nextjs/    # Next.js Server Actions
```

## 모듈 성숙도 레벨

| 레벨 | 이름 | 조건 | 의미 |
|------|------|------|------|
| 🔴 | **POC** | 1개 프로젝트에서 사용 | 동작은 하지만 엣지 케이스 미검증 |
| 🟡 | **Stable** | 2~3개 프로젝트에서 사용, 테스트 존재 | 신뢰할 수 있음, 대부분의 상황에서 동작 |
| 🟢 | **Battle-tested** | 5개+ 프로젝트, 실제 프로덕션 검증 | 거의 수정 없이 바로 사용 가능 |

### 성숙도 자동 업그레이드 규칙

```python
def evaluate_maturity(module):
    usage_count = len(module.usage_history)
    has_tests = module.tests_exist
    production_verified = module.production_count >= 3
    
    if usage_count >= 5 and has_tests and production_verified:
        return "battle_tested"
    elif usage_count >= 2 and has_tests:
        return "stable"
    else:
        return "poc"
```

## 모듈 조합 — 프로젝트 초기화

### 자동 스캐폴딩 워크플로우

```
[명세서의 모듈 매핑 결과]
     │
     ▼
[init_project.py 실행]
     │
     ├── 기본 프로젝트 템플릿 복사 (nextjs_fastapi)
     ├── 필요 모듈들을 프로젝트에 자동 주입
     ├── DB 마이그레이션 파일 통합
     ├── .env.example에 모든 필요 환경변수 수집
     ├── package.json / requirements.txt 의존성 병합
     └── README.md에 설정 가이드 자동 생성
     │
     ▼
[바로 개발 시작 가능한 프로젝트 구조]
```

### init_project.py 예시

```python
def init_project(project_name: str, module_mapping: dict):
    """명세서 모듈 매핑 결과로 프로젝트 자동 초기화"""
    
    # 1. 기본 템플릿 복사
    copy_template("nextjs_fastapi", project_name)
    
    # 2. 모듈 주입
    for mapping in module_mapping["mappings"]:
        if mapping["status"] in ("available", "partial"):
            inject_module(
                project_path=project_name,
                module_slug=mapping["module_slug"]
            )
    
    # 3. 의존성 통합
    merge_requirements(project_name)
    merge_package_json(project_name)
    
    # 4. DB 마이그레이션 통합
    merge_migrations(project_name)
    
    # 5. 환경변수 수집
    collect_env_vars(project_name)
    
    # 6. README 생성
    generate_readme(project_name, module_mapping)
    
    print(f"✅ 프로젝트 '{project_name}' 초기화 완료")
    print(f"   모듈 {len(available)} 개 주입됨")
    print(f"   신규 개발 필요: {len(unavailable)} 개 기능")
```

```
[프로젝트 완료]
     │
     ▼
[신규 개발한 기능 중 재사용 가능한 것 식별]
     │
     ├── 범용성 판단: "다른 프로젝트에서도 쓸 수 있는가?"
     ├── 분리 가능성: "프로젝트 의존성 없이 독립적으로 동작하는가?"
     └── 품질 기준: "테스트가 있는가? 설정이 환경변수로 분리되었는가?"
     │
     ▼
[모듈화하여 프레임워크에 등록]
     │
     ├── module.json 작성
     ├── 프로젝트 의존성 제거 (범용화)
     ├── 설정 파라미터화 (.env 기반)
```

## 프레임워크 성장 지표

### 추적할 메트릭

| 지표 | 계산 방법 | 목표 |
|------|----------|------|
| **모듈 재사용률** | 재사용 모듈 수 / 전체 기능 수 | 50% → 70% |
| **평균 시간 절약** | 절약 시간 / 전체 시간 × 100 | 30% → 60% |
| **모듈 카탈로그 크기** | 등록된 모듈 수 | 10 → 30 → 50 |
| **Battle-tested 비율** | BT 모듈 / 전체 모듈 × 100 | 0% → 50% |
| **프로젝트당 평균 납품 시간** | 총 시간 / 프로젝트 수 | 감소 추세 |
