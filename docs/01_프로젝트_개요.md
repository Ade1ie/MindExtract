# MindExtract — 프로젝트 개요

## 프로젝트명
**MindExtract** — AI 기반 요구사항 추출 및 개인 개발 프레임워크 시스템

## 한 줄 소개
> 클라이언트의 모호한 아이디어를 AI 인터뷰로 추출하여 **정형화된 명세서**로 변환하고, **개인 프레임워크 모듈을 자동 매핑**하여 수주 프로젝트를 최고 효율로 납품하는 **개인 개발 무기**

## MindExtract의 정체

> ⚠️ MindExtract는 "팔 제품(SaaS)"이 아니라 **"내가 돈을 버는 데 쓸 무기"**입니다.

```
수익 구조:
  MindExtract 자체를 팔아서 돈을 벌 ❌
  MindExtract를 써서 클라이언트 프로젝트를 수주하고 납품 ✅
  → 수익 = 클라이언트 수주 대금
```

## 핵심 문제 정의

### 1인 개발자가 수주 프로젝트에서 겪는 고충

| 단계 | 문제 | 소모되는 시간 |
|------|------|-------------|
| **요구사항 수집** | 클라이언트마다 다른 형식 (카톡, PPT, 구두) → 파편화 | 프로젝트당 10~20시간 |
| **명세서 작성** | 수동으로 구조화 → 빠진 항목 발생 → 나중에 스코프 크립 | 프로젝트당 5~10시간 |
| **개발 착수** | 매번 처음부터 개발 → 과거에 만든 비슷한 기능도 재활용 못함 | 프로젝트당 40~80시간 |
| **견적 산출** | 감으로 산출 → 저가 수주 or 과다 견적으로 기회 상실 | 프로젝트당 2~5시간 |

### 근본 원인
- 요구사항 수집 과정이 **표준화되지 않음**
- 축적된 코드가 **재사용 가능한 모듈로 정리되지 않음**
- 명세서 ↔ 내 개발 역량 간의 **자동 매핑이 없음**

## MindExtract가 해결하는 것

### 수주 파이프라인의 완전 자동화

```
[클라이언트 첫 접촉]
     │
     │ MindExtract 인터뷰 링크 전달
     ▼
[AI 인터뷰] ← 클라이언트가 직접 대화 (or 나와 함께)
     │
     │ 어떤 형태의 입력이든 → 통일된 포맷
     ▼
[정형화된 명세서] ← 도메인/기능/비기능 모두 구조화
     │
     ├──→ [프레임워크 모듈 자동 매핑]
     │      ├── ✅ 인증 모듈 (있음) → 바로 적용
     │      ├── ⚠️ 채팅 모듈 (부분) → 커스터마이징 필요
     │      └── ❌ 지도 API (없음) → 새로 개발
     │
     ├──→ [자동 견적 산출]
     │      └── 예상 시간 × 시급 = 견적
     │
     └──→ [AI 코딩 도구용 프롬프트 (JSON)]
            └── Cursor/v0에 즉시 주입 가능
```

## 핵심 가치 3가지

### 1. 정형화된 명세서 템플릿 시스템
**어떤 형태의 클라이언트 입력이든 → 하나의 통일된 명세서로 변환**

- 10명의 클라이언트 = 10개의 동일 포맷 명세서
- 명세서 간 **비교/관리** 가능
- 빠진 요구사항 **자동 탐지**
- 요구사항 변경 시 **diff 추적** → 스코프 크립 방어

### 2. 개인 프레임워크 모듈 시스템
**프로젝트를 할수록 프레임워크가 성장 → 다음 프로젝트가 더 빨라지는 복리 효과**

- 자주 사용하는 기능을 **독립된 모듈로 축적**
- 새 명세서가 나오면 **필요한 모듈을 자동 추천/조합**
- 처음 5개 프로젝트: 모듈 구축에 시간 투자
- 이후 프로젝트: **50~70% 시간 절감** (축적된 모듈 재사용)

### 3. 자동 견적 산출
**명세서 복잡도 + 프레임워크 재사용률 → 정확한 견적**

- 감이 아닌 **데이터 기반** 견적
- 과거 프로젝트 실적 반영으로 점점 정확해짐
- 클라이언트에게 **견적 근거를 논리적으로 제시** 가능

## 기술 스택 요약

| 영역 | 기술 선택 | 선택 근거 |
|------|----------|----------|
| AI/백엔드 | **Python + FastAPI + LangGraph** | 핵심 역량, 멀티 에이전트 상태 관리 |
| LLM | **OpenAI GPT-4o** (초기) | 최고 퀄리티 우선 확보 |
| 프론트엔드 | **Next.js (App Router) + shadcn/ui** | AI 코딩 도구 호환성 (Vibe Coding) |
| 인프라 | **AWS EC2 + Coolify** | 비용 효율 + 자동화 |
| 데이터베이스 | **PostgreSQL** | LangGraph 체크포인팅 + 명세서/모듈 관리 |

## LangGraph 파이프라인 요약

```
Analyzer → Interviewer → Compiler → Validator
  → Template Standardizer (정형화)
  → Framework Mapper (모듈 매핑)
  → Estimator (견적 산출)
  → [정형 명세서 + 모듈 구성표 + 견적서 + JSON 프롬프트]
```

## 개발 전략
**"바이브 코딩(Vibe Coding)"** — 프론트엔드/인프라 약점은 AI 코딩 도구(v0, Cursor)로 보완하고, **핵심 AI 파이프라인과 프레임워크 모듈 설계에 집중**
