# 기술 아키텍처 — AI/백엔드 (LangGraph 멀티 에이전트 파이프라인)

## 아키텍처 개요

MindExtract의 백엔드는 **7개 노드**로 구성된 LangGraph 기반 멀티 에이전트 파이프라인이다.
기존 4개 노드(Analyzer→Interviewer→Compiler→Validator)에 **3개 신규 노드**를 추가하여
클라이언트 요구사항 수집 → 정형 명세서 생성 → 프레임워크 매핑 → 견적 산출까지의 **전 과정을 자동화**한다.

---

## 왜 LangGraph인가?

| 요구사항 | 기본 LangChain | LangGraph |
|---------|--------------|-----------|
| 복잡한 의사결정 트리 탐색 | ❌ 선형적 파이프라인 | ✅ 방향성 그래프 |
| 인터뷰 상태(State) 명시적 관리 | ❌ 암시적 메모리 | ✅ TypedDict 기반 전역 상태 |
| 순환(Loop) 및 자가 교정 | ❌ 한계 | ✅ 조건부 라우팅 |
| 멀티 에이전트 협업 | ❌ 단일 프롬프트 한계 | ✅ 에이전틱 RAG 패턴 |
| 장기 세션 컨텍스트 보존 | ❌ 컨텍스트 증발 | ✅ 예측 가능한 상태 전이 |
| 세션 복원 (체크포인팅) | ❌ 수동 구현 | ✅ PostgresSaver 내장 |

## 전체 파이프라인 흐름 (7개 노드)

```
[클라이언트 입력]
     │
     ▼
┌──────────────────────────┐
│  1. Analyzer Node         │ ← 의도 분석기
│  (도메인/유형/누락 분석)    │
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│  2. Interviewer Node      │ ← AI 인터뷰어 (순환 루프)
│  (객관식/추천형 질문)      │ ◄──┐
└────────────┬─────────────┘    │
             │                   │ 정보 부족 시 재질문
             │ 정보 충분         │
             ▼                   │
┌──────────────────────────┐    │
│  3. Compiler Node         │ ← PRD 컴파일러
│  (마크다운 PRD 생성)       │    │
└────────────┬─────────────┘    │
             │                   │
             ▼                   │
┌──────────────────────────┐    │
│  4. Validator Node        │ ← QA 검증기
│  (논리 검증 + JSON)       │    │
└────────────┬─────────────┘    │
             │                   │
        품질 미달 ───────────────┘
             │
        품질 통과
             │
             ▼
┌──────────────────────────┐
│  5. Template Standardizer │ ← 🆕 정형화 엔진
│  (통일된 명세서 템플릿)     │
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│  6. Framework Mapper      │ ← 🆕 프레임워크 매핑
│  (모듈 자동 매핑/추천)     │
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│  7. Estimator Node        │ ← 🆕 견적 산출
│  (작업량/비용 자동 계산)    │
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│  Output                   │
│  ├── 정형 명세서 (MD)      │
│  ├── 모듈 구성표           │
│  ├── 견적서               │
│  └── AI 코딩 프롬프트 (JSON)│
└──────────────────────────┘
```

## 기존 노드 상세 설계 (Node 1~4)

### Node 1: Analyzer (의도 분석기)

**역할**: 클라이언트의 초기 입력을 분석하여 메타데이터 생성

**출력 (State에 기록)**:
```python
{
    "domain": "marketplace",           # 도메인 분류
    "product_type": "mobile_app",      # 제품 유형
    "functional_gaps": [               # 기능적 누락 항목
        "authentication_method",
        "payment_system",
        "search_algorithm",
    ],
    "non_functional_gaps": [           # 비기능적 누락 항목
        "scalability_target",
        "response_time_sla",
    ],
    "gap_severity": 0.85,              # 누락 수준 (0~1)
    "estimated_interview_rounds": 5    # 예상 인터뷰 라운드 수
}
```

### Node 2: Interviewer (AI 인터뷰어)

**역할**: Analyzer 메타데이터 기반으로 **객관식/추천형 후속 질문**을 동적 생성하여 클라이언트와 상호작용

**순환 루프 조건**:
- `gap_severity > 0.2` → 추가 질문 (루프 계속)
- `gap_severity <= 0.2` → 정보 충분 (Compiler로 이동)

**질문 형태**:
```json
{
    "question": "결제 시스템은 어떤 방식을 원하십니까?",
    "type": "multiple_choice",
    "options": [
        {"label": "에스크로 (안전결제)", "description": "구매자 확인 후 판매자에게 대금 전달"},
        {"label": "직거래 기반 포인트 충전", "description": "앱 내 포인트로 거래"},
        {"label": "외부 결제 연동 (PG사)", "description": "토스/카카오페이 등"},
        {"label": "결제 기능 없음", "description": "오프라인 직거래만"}
    ],
    "recommendation": "에스크로 (안전결제)",
    "recommendation_reason": "마켓플레이스에서 거래 안전성 확보를 위해 가장 권장"
}
```

### Node 3: Compiler (PRD 컴파일러)

**역할**: 대화 이력을 종합하여 마크다운 PRD 초안 구조화

**출력**: 자유 형식의 상세 PRD (아직 정형화 전 단계)
- 문제 정의, 타겟 유저, 기능 명세, 엣지 케이스, 비기능 요구사항 등

### Node 4: Validator (QA 검증기)

**역할**: PRD 초안의 논리적 무결성 검증 + 자가 교정 루프

**자가 교정 흐름**:
```
검증 결과 품질 임계치(quality_score < 0.75) 미달
  → 반려 피드백을 State에 기록
  → 조건부 라우팅으로 Compiler 재실행
  → 최대 재시도: 3회
```

## 🆕 신규 노드 상세 설계 (Node 5~7)

### Node 5: Template Standardizer (정형화 엔진)

**역할**: Validator를 통과한 자유 형식 PRD → **내 정형화된 명세서 템플릿**으로 변환

**왜 필요한가?**
- Compiler가 생성하는 PRD는 프로젝트마다 형식이 다를 수 있음
- 여러 클라이언트의 명세서를 **비교/관리/diff 추적**하려면 동일한 구조가 필수
- 정형화된 명세서여야 다음 노드(Framework Mapper)가 정확하게 모듈을 매핑 가능

**입력**: 자유 형식 PRD (Compiler 출력)

**출력**: 정형화된 명세서 (고정된 섹션 구조)
```json
{
    "spec_version": "1.0",
    "metadata": {
        "client_id": "uuid",
        "project_name": "당근마켓 클론",
        "domain": "marketplace",
        "created_at": "2026-05-02",
        "spec_hash": "sha256..."     // diff 추적용
    },
    "sections": {
        "problem_definition": { ... },
        "target_users": { ... },
        "features": [
            {
                "id": "F001",
                "category": "auth",
                "name": "소셜 로그인",
                "description": "...",
                "acceptance_criteria": ["AC1", "AC2"],
                "priority": "P0",
                "edge_cases": ["EC1", "EC2"],
                "estimated_complexity": "medium",     // Estimator 연동
                "framework_module_hint": "auth_social" // Mapper 연동
            }
        ],
        "non_functional": { ... },
        "data_model": { ... },
        "architecture": { ... },
        "constraints": [ ... ]
    }
}
```

### Node 6: Framework Mapper (프레임워크 매핑)

**역할**: 정형화된 명세서의 각 기능을 **내 개인 프레임워크의 모듈 카탈로그**와 자동 매칭

**입력**: 정형화된 명세서 + 프레임워크 모듈 카탈로그 (DB에서 조회)

**매핑 로직**:
```python
# 각 기능별로 매핑 결과 생성
{
    "feature_id": "F001",
    "feature_name": "소셜 로그인",
    "mapping_result": {
        "status": "available",          # available | partial | unavailable
        "module_id": "auth_social_v2",
        "module_name": "소셜 로그인 모듈",
        "module_version": "2.1.0",
        "maturity": "stable",           # poc | stable | battle_tested
        "customization_needed": [
            "카카오 로그인 OAuth 설정 변경",
            "프로필 필드 매핑 수정"
        ],
        "estimated_hours_saved": 12,    # 이 모듈 덕분에 절약되는 시간
        "estimated_hours_custom": 2     # 커스터마이징에 필요한 시간
    }
}
```

**출력**: 모듈 구성표
```
프로젝트: 당근마켓 클론
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 재사용 가능 (4개 모듈)
  ├── auth_social_v2    소셜 로그인      [stable]    12h 절약, 2h 커스텀
  ├── auth_jwt_v3       JWT 인증         [battle_tested] 8h 절약, 0.5h 커스텀
  ├── file_upload_v1    이미지 업로드    [stable]    6h 절약, 1h 커스텀
  └── notification_v2   푸시 알림       [stable]    10h 절약, 3h 커스텀
  
⚠️ 부분 재사용 (2개 모듈)
  ├── chat_basic_v1     실시간 채팅      [poc]       4h 절약, 8h 추가 개발
  └── search_v1         검색/필터       [poc]       3h 절약, 6h 추가 개발

❌ 신규 개발 필요 (3개 기능)
  ├── 위치 기반 서비스 (지도 API)        예상 16h
  ├── 에스크로 결제 시스템              예상 24h
  └── 신고/차단 시스템                 예상 8h
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
총 재사용 절약: 43시간
총 커스터마이징: 20.5시간
총 신규 개발: 48시간
```

### Node 7: Estimator (견적 산출)

**역할**: Framework Mapper 결과를 기반으로 **작업량, 비용, 일정을 자동 산출**

**입력**: 모듈 구성표 + 과거 프로젝트 실적 데이터 (DB에서 조회)

**산출 로직**:
```python
총_예상_시간 = (
    sum(모듈별_커스터마이징_시간)           # 재사용 모듈 커스텀
    + sum(부분_모듈_추가개발_시간)          # 부분 모듈 확장
    + sum(신규_기능_예상_시간)             # 신규 개발
    + 통합_테스트_시간                    # 전체의 15~20%
    + 배포_및_인프라_시간                  # 고정 8~16시간
    + 버퍼 (20%)                         # 예상치 못한 이슈
)

견적_금액 = 총_예상_시간 × 시급
```

**출력**: 견적서
```json
{
    "project_name": "당근마켓 클론",
    "client_id": "uuid",
    "breakdown": {
        "module_customization": {"hours": 20.5, "cost": 615000},
        "partial_module_dev": {"hours": 14, "cost": 420000},
        "new_feature_dev": {"hours": 48, "cost": 1440000},
        "integration_testing": {"hours": 16.5, "cost": 495000},
        "deployment": {"hours": 12, "cost": 360000},
        "buffer_20pct": {"hours": 22.2, "cost": 666000}
    },
    "summary": {
        "total_hours": 133.2,
        "hourly_rate": 30000,           // 시급 (원)
        "total_cost": 3996000,          // 총 견적
        "estimated_duration_weeks": 3.3, // 주당 40시간 기준
        "framework_savings_pct": 38.7   // 프레임워크 덕분에 절약된 비율
    },
    "comparison": {
        "without_framework_hours": 217,  // 프레임워크 없이 개발 시
        "time_saved_hours": 83.8,        // 절약된 시간
        "cost_saved": 2514000            // 절약된 비용
    }
}
```

## State 객체 설계 (확장)

```python
from typing import TypedDict, List, Optional

class InterviewState(TypedDict):
    # === 클라이언트/프로젝트 정보 ===
    client_id: str
    project_id: str
    
    # === 사용자 입력 ===
    initial_prompt: str
    messages: List[dict]
    
    # === Analyzer 출력 ===
    domain: str
    product_type: str
    functional_gaps: List[str]
    non_functional_gaps: List[str]
    gap_severity: float
    
    # === Interviewer 상태 ===
    current_round: int
    total_rounds: int
    collected_requirements: dict
    
    # === Compiler 출력 ===
    prd_draft: Optional[str]               # 자유 형식 PRD
    
    # === Validator 출력 ===
    qa_feedback: Optional[str]
    is_approved: bool
    retry_count: int
    quality_score: float
    
    # === 🆕 Template Standardizer 출력 ===
    standardized_spec: Optional[dict]      # 정형화된 명세서
    spec_version: int
    spec_hash: str                         # diff 추적용 해시
    
    # === 🆕 Framework Mapper 출력 ===
    module_mapping: Optional[dict]         # 모듈 매핑 결과
    available_modules: List[dict]          # 재사용 가능
    partial_modules: List[dict]            # 부분 재사용
    missing_features: List[dict]           # 신규 개발 필요
    total_hours_saved: float
    
    # === 🆕 Estimator 출력 ===
    estimate: Optional[dict]               # 견적 데이터
    total_hours: float
    total_cost: float
    estimated_duration_weeks: float
    
    # === 메모리 관리 ===
    conversation_summary: Optional[str]
    system_prompt_json: Optional[dict]     # AI 코딩 도구용
```

## 백엔드 API 설계 (FastAPI)

### 클라이언트 관리

| Method | Endpoint | 설명 |
|--------|----------|------|
| `POST` | `/api/clients` | 클라이언트 등록 |
| `GET` | `/api/clients` | 클라이언트 목록 |
| `GET` | `/api/clients/{client_id}` | 클라이언트 상세 |
| `PATCH` | `/api/clients/{client_id}` | 클라이언트 정보 수정 |

### 프로젝트 관리

| Method | Endpoint | 설명 |
|--------|----------|------|
| `POST` | `/api/projects` | 프로젝트 생성 |
| `GET` | `/api/projects` | 전체 프로젝트 목록 |
| `GET` | `/api/projects/{project_id}` | 프로젝트 상세 |
| `PATCH` | `/api/projects/{project_id}/status` | 상태 변경 |

### 인터뷰 세션

| Method | Endpoint | 설명 |
|--------|----------|------|
| `POST` | `/api/interview/start` | 인터뷰 시작 (클라이언트/프로젝트 연결) |
| `POST` | `/api/interview/{session_id}/respond` | 질문 응답 |
| `GET` | `/api/interview/{session_id}/resume` | 세션 복원 |
| `POST` | `/api/interview/{session_id}/compile` | PRD → 정형 명세서 → 매핑 → 견적 전체 파이프라인 실행 |

### 명세서 관리

| Method | Endpoint | 설명 |
|--------|----------|------|
| `GET` | `/api/specs/{project_id}` | 프로젝트 명세서 조회 |
| `GET` | `/api/specs/{project_id}/versions` | 명세서 버전 이력 |
| `GET` | `/api/specs/{project_id}/diff/{v1}/{v2}` | 버전 간 차이 |
| `GET` | `/api/specs/{project_id}/export?format=md\|json` | 내보내기 |

### 프레임워크 모듈 관리

| Method | Endpoint | 설명 |
|--------|----------|------|
| `GET` | `/api/framework/modules` | 모듈 카탈로그 |
| `POST` | `/api/framework/modules` | 모듈 등록 |
| `PATCH` | `/api/framework/modules/{module_id}` | 모듈 업데이트 |
| `GET` | `/api/framework/modules/{module_id}/usage` | 모듈 사용 이력 |

### 견적 관리

| Method | Endpoint | 설명 |
|--------|----------|------|
| `GET` | `/api/estimates/{project_id}` | 프로젝트 견적서 |
| `PATCH` | `/api/estimates/{project_id}` | 견적 수동 조정 |
| `GET` | `/api/estimates/{project_id}/export` | 견적서 내보내기 (PDF) |

### 대시보드 (개인용)

| Method | Endpoint | 설명 |
|--------|----------|------|
| `GET` | `/api/dashboard/overview` | 전체 현황 (진행 중 프로젝트, 수익 등) |
| `GET` | `/api/dashboard/stats` | 통계 (프로젝트별 수익성, 모듈 재사용률 등) |

### 클라이언트 인터뷰 링크 (외부 공개)

| Method | Endpoint | 설명 |
|--------|----------|------|
| `POST` | `/api/links/create` | 인터뷰 링크 생성 |

## 프로덕션 최적화

### 상태 객체 경량화
- 거대한 원문 텍스트 → 외부 스토리지(PostgreSQL)에 저장
- State에는 **식별자, 참조 메타데이터, 수치 데이터**만 유지

### 초기 LLM 구성
- **Phase 1**: OpenAI GPT-4o 단일 체제 (품질 우선)
- **Phase 2**: 하이브리드 구성
  - Analyzer/Interviewer: GPT-4o-mini (빠른 응답)
  - Compiler/Validator/Standardizer: GPT-4o (높은 품질)
  - Mapper/Estimator: GPT-4o-mini + DB 쿼리 (구조적 작업)

### 스트리밍 응답
- 인터뷰 질문 생성 시 SSE(Server-Sent Events) 활용
- 사용자 체감 대기 시간 감소
