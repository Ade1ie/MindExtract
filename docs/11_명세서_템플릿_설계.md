# 정형화된 명세서 템플릿 설계

## 왜 정형화가 필요한가?

### 현실 문제
```
클라이언트 A: 카톡 음성 메시지 5개 → 파편화된 요구사항
클라이언트 B: 파워포인트 20장 → 과도하게 장황
클라이언트 C: "당근마켓 같은 거요" → 정보 부족
클라이언트 D: 노션 페이지 링크 → 구조는 있으나 내 포맷과 불일치
```

### MindExtract의 해결
```
어떤 형태의 입력이든
  → AI 인터뷰로 정보 추출
  → 하나의 동일한 템플릿으로 변환
  → 모든 클라이언트의 명세서를 비교/관리/추적 가능
```

### 기능 카테고리 표준 분류

| 카테고리 | 설명 | 예시 |
|---------|------|------|
| `auth` | 인증/인가 | 소셜 로그인, JWT, 권한 관리 |
| `payment` | 결제/정산 | PG 연동, 에스크로, 환불 |
| `chat` | 메시징/채팅 | 실시간 채팅, 채팅방 관리 |
| `search` | 검색/필터 | 전문 검색, 카테고리 필터 |
| `notification` | 알림 | 푸시, 이메일, SMS |
| `file` | 파일 관리 | 이미지 업로드, S3 연동 |
| `admin` | 관리자 기능 | 대시보드, 유저 관리 |
| `analytics` | 분석/통계 | 사용자 행동, 매출 통계 |
| `social` | 소셜 기능 | 팔로우, 좋아요, 공유 |
| `location` | 위치 기반 | 지도, 주변 검색 |
| `content` | 콘텐츠 관리 | CRUD, 에디터, 태그 |
| `moderation` | 콘텐츠 관리/신고 | 신고, 차단, 자동 필터 |

## 명세서 버전 관리

### diff 추적 메커니즘

```python
import hashlib
import json

def calculate_spec_hash(spec_data: dict) -> str:
    """명세서 데이터의 해시를 계산하여 변경 감지"""
    canonical = json.dumps(spec_data, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256(canonical.encode()).hexdigest()

def generate_diff(spec_v1: dict, spec_v2: dict) -> dict:
    """두 버전 간의 차이를 추출"""
    diff = {
        "added_features": [],
        "removed_features": [],
        "modified_features": [],
        "non_functional_changes": [],
        "constraint_changes": []
    }
    # ... 각 섹션별 비교 로직
    return diff
```

### 버전 히스토리 활용
- **스코프 크립 방어**: 클라이언트가 "이것도 원래 포함이었잖아요" → 버전 diff로 반박
- **변경 이력 추적**: 어떤 요구사항이 언제, 왜 바뀌었는지 기록
- **비용 추가 근거**: 새로 추가된 기능 → 자동으로 추가 견적 산출
