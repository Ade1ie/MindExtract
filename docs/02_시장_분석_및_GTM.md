# 클라이언트 수주 전략 및 워크플로우

## MindExtract 기반 수주 프로세스

### 표준화된 수주 파이프라인

```
[수주 채널에서 문의 수신]
     │
     ▼
[클라이언트 등록 + 프로젝트 생성]
     │
     ▼
[MindExtract 인터뷰 링크 전달]
  "개발 착수 전에 이 링크에서 기획을 먼저 확정해주세요"
     │
     ▼
[AI 인터뷰 → 정형 명세서 자동 생성]
     │
     ▼
[프레임워크 모듈 매핑 + 자동 견적 산출]
     │
     ▼
[견적서 기반 계약 체결]
  → 명세서 = 계약의 일부 (스코프 방어막)
     │
     ▼
[모듈 조합 → 개발 → 납품]
     │
     ▼
[신규 개발 기능 → 프레임워크 환원]
```

## MindExtract가 만드는 차별화

### "다른 프리랜서 vs 나" 비교

| 항목 | 일반 프리랜서 | MindExtract 사용 시 |
|------|-------------|-------------------|
| 요구사항 수집 | 수동 (미팅 3~5회) | **AI 인터뷰 1회** → 정형 명세서 |
| 견적 산출 | 감 기반 | **데이터 기반** (모듈 매핑 + 자동 산출) |
| 견적 근거 | "경험상 이 정도요" | **항목별 시간/비용 breakdown** 제시 |
| 스코프 관리 | 구두 합의 → 분쟁 발생 | **정형 명세서 = 계약 범위** (diff 추적) |
| 개발 속도 | 매번 처음부터 | **프레임워크 모듈 재사용** (30~70% 절약) |
| 추가 요구사항 | "원래 포함이었잖아요" | **명세서 diff → 추가 견적 자동 산출** |

### 클라이언트에게 어필하는 포인트
> "저와 작업하시면 AI가 먼저 기획을 도와드리고, 정확한 견적을 드립니다.  
> 개발 중 요구사항이 바뀌면 변경 사항을 투명하게 추적하여 추가 비용을 명확히 안내드립니다."

## 수주 후 워크플로우 상세

### 1단계: 요구사항 수집 (Day 1~2)

```
1. 클라이언트에게 MindExtract 인터뷰 링크 전달
2. 클라이언트가 자율적으로 AI 인터뷰 진행
   (또는 화상/대면 미팅에서 함께 진행)
3. 정형화된 명세서 자동 생성
4. 내가 명세서를 검토하고 누락 항목 보완
5. 클라이언트에게 명세서 최종 확인 요청
```

### 2단계: 견적 및 계약 (Day 3~4)

```
1. Framework Mapper가 모듈 구성표 자동 생성
2. Estimator가 견적서 자동 산출
3. 견적서 검토 후 수동 조정 (필요시)
4. 클라이언트에게 견적서 + 명세서 전달
5. 합의 후 계약 (명세서 = 계약 범위)
```

### 3단계: 개발 및 납품 (Week 1~N)

```
1. init_project.py로 프로젝트 스캐폴딩 (모듈 자동 조합)
2. 모듈 커스터마이징 → 신규 기능 개발
3. 중간 점검 (명세서 기준으로 진행률 추적)
4. 최종 테스트 → 납품
```

### 4단계: 프레임워크 환원 (납품 후)

```
1. 신규 개발 기능 중 재사용 가능한 것 식별
2. 모듈화 → 프레임워크에 등록
3. 프로젝트 실적 기록 (실제 시간 vs 견적 시간)
4. Estimator 정확도 피드백
```

## 스코프 크립 방어 매뉴얼

### 클라이언트가 "이것도 추가해주세요"라고 할 때

```
1. MindExtract에서 기존 명세서 + 추가 요구사항 비교
2. 자동 diff 생성:
   "기존 명세서 v1에는 [채팅 기능]이 scope_out에 명시되어 있습니다.
    해당 기능 추가 시 예상 작업량: +24시간, 추가 비용: +72만원"
3. 클라이언트에게 diff + 추가 견적 제시
4. 합의 시 명세서 v2로 업데이트 → 계약 수정
```
